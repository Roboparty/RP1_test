# Windows CAN-FD 接入要求

## 支持范围

电机控制网关采用 Linux SocketCAN。Windows 原生周立功 CAN-FD 需要外部 SDK 和设备适配，不作为现成后端提供。PySide6 桌面与电机驱动层分开，设备接入不得把控制循环放到界面线程。

本目录不包含厂商 DLL、头文件、导入库、固件或适配器驱动。设备适配代码须依据目标型号的官方 SDK，不能猜测设备常量、结构体布局或调用约定。

## 接入前确定

| 项目 | 需要的信息 |
| --- | --- |
| 设备 | 型号、硬件版本、固件版本、通道数 |
| SDK | 版本、32/64 位目标、调用约定、官方头文件与库 |
| 部署 | 驱动、DLL 及其依赖、再分发许可 |
| 通道 | 枚举、打开、初始化、开始、复位和关闭语义 |
| 位时序 | 仲裁/数据相位时钟、采样点、SJW 和设备允许的组合 |
| 错误处理 | 错误码、bus-off、USB 断开与重连行为 |
| 时间与队列 | 时间戳单位、发送/接收队列容量、阻塞与超时语义 |

## 适配层职责

1. 把设备与通道配置映射到 SDK 的明确参数。
2. 转换标准/扩展 ID、BRS、DLC 和 CAN-FD 载荷。
3. 支持并发发送、限时接收、接收中断和幂等关闭。
4. 设备缺失、通道占用、DLL 不匹配或初始化失败时返回明确错误。
5. 断线后停止运动并释放通道，恢复后重新执行连接和使能流程。

设备名、通道号与 SDK 后端配置由具体适配器定义。不要直接把 Linux 的 `can0` 当作 Windows 设备标识。

## 设备验收

- 按批准的位时序配置仲裁和数据相位，使用设备读回或 CAN-FD 分析仪确认。
- 检查标准/扩展 ID、BRS、DLC、载荷字节序及收发完整性。
- 在代表性电机负载下记录控制周期、发送延迟、反馈延迟、丢帧和队列溢出；报告均值、P95、P99 与最大值。
- 检查空闲、发送和阻塞接收时的关闭行为，通道关闭后不遗留线程。
- 检查错误配置、通道占用、断开 USB、bus-off、程序崩溃和重启后的安全行为。
- 检查目标 Windows 版本、驱动、SDK、Python ABI 和打包组件能在干净环境复现。
- 保持 Linux SocketCAN 的控制与错误语义一致。

控制频率和老化时长以工位测试计划为准。完成上述设备与安全验收前，应继续使用 Linux 控制网关。
