# 工厂老化上位机验收清单

## 软件与离线验证

- 在干净 Ubuntu 22.04 x86_64 主机上只安装版本化 `.deb`；删除/不挂载源码目录，
  确认应用菜单、systemd 服务、内置 `motors_py` 和默认工位配置均可用。
- 离线安装、升级、卸载后重装均通过；升级保留 `/etc/rp1-factory-hmi`，卸载保留
  `/var/lib/rp1-factory-hmi/records`。
- 所有 Python 单元测试通过，现有 CLI 的参数和返回码保持兼容。
- Fake 后端可以完成配置、CAN 连接、电机发现、使能、轨迹导入、Armed、开始、
  暂停、继续、停止、回默认位和失能。
- 非白名单接口、非法位时序、无 polkit 权限和 bus-off 未恢复时均禁止电机发现。
- 部分电机使能失败必须回滚并失能全部电机；重复使能必须被拒绝。
- 错误状态转换、重复连接、未 Armed 启动、未加载轨迹启动均被拒绝。
- 非法 NPZ（缺字段、列数不符、NaN、错误 limb、超限位、速度突变、首帧差过大）无法进入 Armed。
- 两个客户端选择不同 CAN 时可以并行控制独立模块；选择同一 CAN 时第二个客户端必须被拒绝。
- 任一会话操作租约超时后，网关只停止并释放该会话，其他 CAN 会话继续运行。
- PostgreSQL、InfluxDB 或桌面客户端离线时，本地 CSV 和故障记录仍可保存。

## 界面验收

- Windows/Linux 桌面客户端均可启动，普通操作不显示命令行窗口。
- 主界面只保留“样机配置与连接 / 老化测试 / 关节控制”三个标签页；电机监控和电机标零分别以两个独立弹窗打开。
- 电机标零表每个关节末尾提供独立“标零”，并提供“一键标零全部关节”；执行标零会先停止位置保持、失能全部电机，完成后保持失能。
- 工人不接触 YAML 参数即可完成标准老化流程；管理员才能进入标零和台架设置。
- 导入 YAML 后自动显示电机 ID、类型、型号、零偏、Kp、Kd 和方向，并允许在应用前修改。
- YAML 中的 CAN 接口和位时序不生效；界面能枚举当前 CAN、显示启停/错误状态并从策略白名单选择模式和位率。
- 电机数量按配置动态生成，手臂、单腿、双腿+腰和上身不使用独立硬编码页面。
- “新建模块窗口”可同时打开两个独立窗口，窗口标题能区分部位、样机和 CAN。
- 每个电机显示目标/实际角度、误差、速度、力矩、温度、母线电压/电流、错误码和反馈更新时间。
- 老化运行中实时显示累计时长、循环次数、跟踪 RMS/最大误差、峰值力矩、当前温度/温升和错误样本；完成后可保存 CSV 并准备下一组。
- 关节控制页可按整组目标角度和设定速度平滑移动；目标越过配置限位或速度上限时网关拒绝执行，“立即停止并保持”可随时结束手动移动。
- 关节控制页不包含轨迹录制或轨迹导出功能。
- 故障栏明确区分“驱动器已报告故障”和“根据数据推测的疑似故障点”。
- 软件失能按钮旁持续显示“不能替代物理急停”。

## 真机功能验收

按单臂、单腿、双腿+腰、上身顺序逐项执行：

1. CAN 连接、反馈读取和安全失能；
2. 当前位姿与配置零位核对；
3. 低速单周期轨迹；
4. 暂停保持、继续、回默认位和正常停止；
5. 20 分钟循环老化与报告生成；
6. 既有 CLI 与上位机回放结果对比。

多链路验收至少增加以下组合：

1. 单臂窗口绑定 can0、单腿窗口绑定 can1，同时完成发现、使能和低速循环；
2. 第三个窗口选择 can0 时明确报告占用冲突；
3. 关闭或强制终止其中一个窗口后，仅对应模块安全停机并在租约超时后释放接口；
4. 经典 CAN 的 125/250/500/1000 kbit/s 及 CAN-FD 的批准数据位率逐档验证；
5. 非白名单位率、重复总线绑定和运行中更换接口均被拒绝。

每个总成必须从界面依次完成“连接 CAN → 发现电机 → 二次确认使能”，不得提前在
终端手工拉起 CAN 或调用电机使能脚本。真机验收必须在空载、限速、机械防护和物理
急停有效的条件下由两人执行并签字。

控制网关应稳定维持配置的 200 Hz 指令周期，UI 刷新、曲线绘制和网络传输不得在控制线程运行。验收报告应记录实际周期均值、P95/P99 抖动和最大间隔。

## 故障注入

- 单电机 `error_id`：定位到 motor_id、关节和 CAN 口并停止。
- 单电机反馈冻结：报告 stale；不得误判整条总线。
- 同一 CAN 口全部反馈冻结：优先提示总线、适配器、线束或该路供电。
- 控制心跳停止：在配置超时内停止采集与回放。
- 操作电脑断网或进程退出：Linux 网关在租约超时内停止并失能。
- 母线欠压：结合 `error_id=0x03` 和电压趋势提示电源/BMS；只有电压证据不足时标记为疑似。
- 温度、力矩持续上升：提示过载、摩擦或卡滞排查，不直接断言机械损坏。
- 平台 API/InfluxDB/NAS 不可用：不影响本地安全停机。

任何故障注入都必须在空载、限速、机械防护和物理急停有效的条件下进行。

## Windows 原生 CAN-FD 验收

该项仅在周立功型号和官方 SDK 固定后执行：

- 设备枚举、通道映射、重复打开和异常关闭；
- 1 Mbps 仲裁、5 Mbps 数据相位及 CAN-FD 帧收发；
- 单口和多口 200 Hz MIT 批量控制；
- 与 Linux SocketCAN 对比反馈延迟、丢帧、周期抖动和 CPU 占用；
- 8 小时循环老化；
- 拔 USB、断总线、驱动器故障、欠压及程序崩溃安全停机；
- 目标 Windows 版本、驱动、DLL 和 `motors_py.pyd` 安装包复现。

未完成以上真机验收时，Windows 后端只能标记为“工程预览”，不得用于生产。
