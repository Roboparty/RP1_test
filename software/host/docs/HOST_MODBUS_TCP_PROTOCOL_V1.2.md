# LFD835 Host Protocol V1.2 — HMI与PLC V1.5配套契约

契约由电脑2任务 `01a12551-dd05-7740-a489-6e89857e5094` 最终消息
`msg_0609caf1dcbfce2c016aca2ccd9b248191b944746cd11c603c` 冻结。
PLC软件版本V1.5，Modbus协议版本0x0102，两者不同。
本次仅修改HMI源码并离线验证。电脑2报告PLC37项离线测试通过，TIA尚未编译；
这不是在线PLC已升级或实物联调通过的证明。

## 地址、单位与语义

PDU零起始，HR0=0x4C46，HR1=0x0102；FC03每次整帧读取HR0～31，共32Word。
命令HR32～37、控制键0x835A、先写载荷再提交CommandSeq的顺序不变。
HR21～23保留V1.1复位回执和故障来源，AcceptedCommandSeq仍只表示命令接收。

| 地址 | 字段 | 冻结语义 |
| --- | --- | --- |
| HR28 | PS1FeedbackFlags | 下表的反馈有效性与锁 |
| HR29 | PS1StatusSeq | 真实1007读取成功才递增；STOP/端口装载不递增；16位环绕 |
| HR30 | PS1PowerCycle | MainReady上升递增；16位环绕；CPU启动清零 |
| HR31 | PS1StatusAgeMs | 有效0～4999ms，无效65535；按扫描离散更新 |
| HR12～15 | VS1～VS4电压 | 0～50V，1mV/计数；50000=50.000V，与0100/0101相同 |
| HR16～19 | CH电流 | 0～50A，1mA/计数 |

PS1的HR8～11和HR36～37也保持1mV/mA每计数。PS1设定允许1～60000mV/mA，
该60V/A设定上限与50V变送器量程是不同参数。

| HR28位 | 含义 |
| --- | --- |
| bit0 | MainReady连续5秒计时完成，**不证明PS1自检完成** |
| bit1 | 端口装载完成，**不证明设备健康** |
| bit2 | 本周期真实1007状态有效 |
| bit3 | 本周期STOP应答后真实OFF确认；正常ON可以保留，**不代表当前OFF** |
| bit4 | 人工重启锁 |
| bit5 | 恢复耗尽 |
| bit6 | 本周期测量有效 |
| bit7 | 本周期设定回读有效 |
| bit8～15 | 保留，必须为0；非零禁止控制，不猜测其含义 |

HR2 bit3收紧为真实设备就绪；bit4是最后真实输出，失效后不能解释为当前OFF。
TCP成功及本机StatusCounter递增只表示TCP快照，不表示PS1有新反馈。

## 本地确认与输出准入

`plc/freshness.py` 以会话内单调时钟追踪HR29推进，独立于TCP轮询：

- 新会话先建立基线，必须观察到新的真实状态推进。
- 重复序号不续期限，65535→0算推进；反向或半范围以上跳变保守视为重置。
- 周期变化、掉电、反馈无效、会话断开或已知CPU重启撤销本地确认。
- 同时受HR31和本地单调时钟限制；5秒无推进即失效。
- 16位计数不是持久启动身份；重启恰好返回相同计数无法单凭这几个Word识别。
  外部已知CPU重启时调用 `notify_cpu_restart()` 撤销确认。

PS1输出ON与CH请求集中通过 `state_machine.py::_write_checked()`：要求V1.2、
新鲜TCP状态、PLC/Host/MainReady、PS1真实状态推进、bit0/1/3/6/7、Applied、
无Rejected、无控制/通信/设备/主机故障、无人工锁/恢复耗尽，模拟量范围有效。
CH另须真实输出ON，已知物理许可为False则拒绝。脉冲与心跳的保留ON载荷也检查。
冷启动MainEnable只用于顺序准备，不能提前许可PS1或CH。

故障检查在回执推进前执行。同帧SetpointApplied、回显值、AcceptedSeq成功且有
故障时，先停机，绝不先发送ON。数值匹配不能跳过有效性与Applied/Rejected检查。

PLC三类反馈任一5秒未刷新，必须撤有效位/许可并人工锁；HMI据此停机。HR29
不是测量或设定的独立序号，两类有效期由PLC的bit6/7及人工锁证明。
纯F003设定不符、其他反馈健康时，仅撤PS1/CH运行请求、保留KM0；通信、设备故障、
过期或非法状态则撤KM0。**没有允许通信故障保持主回路的恢复例外**。

失效时UI实际输出、测量、设定显示“未确认”，不把默认False和零作为确认；
趋势使用相同有效性快照，不用无效零值绘制正常曲线。

## 版本与有界时间预算

0100仅可监控且无复位结果；0101仅可监控但仍解码复位与故障来源；0102保留
全部0101能力并支持新控制。未知版本拒绝。控制连接第一次写之前检查版本。
旧版页面启动、复位、应用设定禁用并提示配套升级。
历史28Word YAML只在内存扩为32Word并补固定字段，不自动覆写用户配置。

命令接收/复位仍为5000ms；复位沿用最早100ms成功、2s仍锁存失败、NOT_SAFE
同扫描拒绝，必须匹配最终回执，不依据旧故障位提前失败。

MainReady后通信阶段预算为PLC固定5秒计时+原PS1阶段预算+2次轮询余量，默认
10.4s；这不是PS1自检完成证明或故障恢复宽限。其余阶段保留既有命令/KM0/PS1超时。
冷启动另设一次性总上限，按所有阶段预算相加：

`5000 + km0_timeout_ms + 3*ps1_timeout_ms + 9*command_timeout_ms + 2*poll_ms`

默认70400ms；多窗口收据使用同一上限。该值是主机各阶段的保守总上限，**不是
PLC恢复流程承诺时间**。阶段故障/超时会更早停止，轮询或重试不续总期限。
仍需电脑2明确实际最长启动/恢复时间、重试次数、人工锁清除条件；HMI当前保守
拒绝锁状态ON，不发明解锁命令，不放宽通信故障互锁。
