# 电机故障恢复

电机故障复位和 PLC 控制故障复位是不同入口。PLC 故障与反馈要求见 [PLC 对接](plc-integration.md)。

## 操作顺序

1. 停止测试并明确失能。电机复位拒绝软件仍使能的状态，不先打断健康电机保持再拒绝。
2. 人工点击“复位电机故障”。网关检查操作员令牌与控制租约，关闭旧连接后仅打开通信，不调用隐含使能的连接流程。
3. 获取各配置电机的新反馈。无反馈、非有限位置或超时均失败；尚未取得反馈时不发送清错。
4. 每个人工请求只发送一轮清错，不自动重试；各电机须有两次反馈时间推进且新 `error_id=0`。缓存零码和函数返回不代表成功。
5. 成功后为 `CONNECTED`、`motors_enabled=False`，清除旧轨迹、预检和回放对象。用户确认安全条件后显式使能，再重新导入轨迹、预检、启动。

“回默认位”只接受已连接、已使能且反馈健康的 CONNECTED/ARMED/COMPLETED；FAULT 或失能状态不能隐式清错、重连和使能。健康回位按半 KP 1 秒、正常 KP 2 秒执行，KD 不变。

发现和使能前要求每台电机两次新反馈；发现可读取非零故障码，使能前拒绝故障与越限位置。使能后再取得至少一次新反馈并查位置，才开始保持；失败尝试整组失能，不自动恢复运动。

## 新鲜性与中断

确认依据 `MotorSample.timestamp_s` 和真实 SDK 接收推进，重复读缓存不刷新年龄。各确认阶段逻辑期限为 `min(1.0秒, stale_seconds)`，默认 1 秒，每 5ms 检查中断。诊断与界面的反馈超时仍分别按其配置处理。

`refresh_feedback()` 只使用已定义的安全查询白名单 DM/LRO/XYN，不调用可能隐含使能的 EVO 查询。无安全查询且无真实主动反馈时拒绝准入，不能制造新鲜时间；使能后仅接受真实接收更新。

软件失能/断开先验证权限和租约，再设置中断信号，旧动作受 motion epoch 限制。SDK 原生调用可能阻塞，中断只能在调用之间处理；逻辑期限不是实时电气停机保证。通信中断时失能发送可能失败，软件标志不证明物理失能。

位置保持每 50ms 先查故障、非有限/缺失/过期反馈，再发目标。失能/断开使此前排队指令失效，不在停机后重放旧使能或回位。

## 代码与验证入口

- `factory_hmi/core/controller.py`：发现、使能、故障复位、反馈等待和位置保持。
- `factory_hmi/core/backend.py`：接收推进和安全反馈查询。
- `factory_hmi/core/service.py`、`factory_hmi/gateway/app.py`：`POST /api/v1/motors/reset-fault`、权限、租约与串行调用。
- `factory_hmi/client.py`、`factory_hmi/desktop/app.py`：独立复位请求、pending 禁用和成功/失败提示。
- `tests/test_motor_fault_recovery.py`：fake 后端的顺序、新反馈、超时、中断、权限与失败失能回归。

mock 和离屏验证不证明真实 CAN、固件反馈或现场恢复通过。上线按 [运维](../../docs/operations.md) 核对安装版本、实际新进程及配置，真实设备恢复须另行现场验收。
