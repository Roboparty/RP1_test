# 电机故障恢复顺序修正（2026-10-12）

本节记录 2026-10-12 的源码调整与离线验证；后续本地构建范围见 `LOCAL_CONTROL_BUILD.md`，实际安装版本须以本机 dpkg 查询为准。未连接实物验证。原有原始 CSV 本地保存、平台数据审批以及 PLC V1.2 协议均不因本改动改变。

## 操作顺序与状态

1. 已运行的测试先停止，电机明确执行失能；复位入口拒绝仍处于软件使能状态的电机，不打断健康电机的位置保持后再拒绝。
2. 人工点击新增的“复位电机故障”。网关在原有操作员令牌和控制租约检查后调用独立复位接口；先关闭旧电机连接，再仅打开通信，不调用包含使能的 `backend.connect()`。
3. 获取每台配置电机的新反馈，保留故障码用于检查。无反馈、非有限位置或等待超时均停止流程，尚未到清错时不发送清错命令。
4. 每个人工复位请求只发送一轮清错，不自动重试。随后必须观察每台电机两次反馈更新时间推进，并且新反馈 `error_id=0`；缓存零错误码、函数正常返回或接口 UP 均不能替代确认。
5. 成功后状态为 `CONNECTED`、`motors_enabled=False`，清除旧轨迹、预检和回放对象，不启动位置保持或回默认位。用户再次确认安全条件后使能，并重新导入轨迹、预检、启动。

“回默认位”现在只接受已经连接、使能且反馈健康的 CONNECTED/ARMED/COMPLETED 状态；FAULT 或失能状态不会隐式清错、重连或使能。健康回位保持原半 KP 1 秒、正常 KP 2 秒及 KD 不变的动作。

发现电机和使能之前同样要求每台电机两次新反馈；发现阶段允许读取非零故障码，使能之前拒绝非零故障码及位置越限。使能完成后，必须再取得每台电机至少一次新反馈并检查位置，才开始位置保持。任一电机使能失败或随后无反馈时，保留故障并尝试整组失能，不恢复运动。

## 新鲜性、超时和中断

- 确认以后端 `MotorSample.timestamp_s` 的实际推进为依据；硬件后端由 SDK 接收计数推进更新该时间，并非重复读取缓存就刷新。已有单调反馈序号时，不再用旧 `response_count=0` 代替序号推进；接收计数缺失或读取失败时，也不再因为读取缓存而刷新反馈年龄。
- 每个确认阶段的逻辑期限是 `min(1.0秒, 原 stale_seconds)`，默认 1 秒。等待每 5ms 检查中断；原诊断 2 秒反馈失效门限和界面 200ms 显示门限没有放宽。
- `refresh_feedback()` 保留型号白名单 DM/LRO/XYN，不调用 EVO 会隐含使能的状态查询。型号缺少安全查询且没有真实主动反馈时会拒绝准入，须先核实型号协议，不能为兼容而制造新鲜时间。
- 硬件后端使能后不主动发上述失能查询，只接受真实接收更新。不能取得新反馈时保持故障，不用运动帧绕过确认。
- 软件失能/断开仍先校验权限与租约，再无锁设置中断信号；等待恢复的旧网关动作仍受现有 motion epoch 检查。发现、使能、故障复位和回位共享取消信号。
- SDK 原生调用本身可能阻塞，中断信号只能在调用之间处理；1 秒是确认阶段的逻辑期限，不是实时硬中断或电气停机时间保证。通信断开时失能发送也可能失败，软件标志不证明物理电机已失能。
- 位置保持每 50ms 检查故障、非有限位置、缺失/过期反馈；先检查再发本轮目标。失败后不继续保持。

## 验证与 PLC 对接状态

本轮只运行 FakeMotorBackend、内存 ASGI 网关和 Qt offscreen 测试，未打开物理 CAN 或操作 PLC/电机。最终整套 HMI 回归为 **394 项测试、119 项子测试通过**，1 项既有依赖警告；包含新增电机恢复用例、既有 PLC V1.2/多窗口/回位/界面/记录与审批用例。最后故障提示文案调整后另通过界面定向回归 **18 项测试、108 项子测试**，它们是整套回归的子集，不相加；1600×900离线渲染核对新按钮未截断。另通过 `git diff --check`、Python 语法检查及 `scripts/check-release.py`。测试日志和渲染图片保存在本机临时目录，不提交到仓库。

PLC 方面，当前 HMI 的 V1.2 / HR1=0x0102、32 Word、1mV/计数、真实反馈推进与锁态拒绝已有源码及离线回归；协议相关 17 文件仍与 2026-10-11 manifest 匹配。源码调整时安装包只读查询为 `rp1-test-hmi 2.0.4+ubuntu24.04`；升级包文件后，已有进程仍须正常退出并重开才加载新代码。

电脑2“核对 PLC 上电通信”最新已完成轮次报告，固定100ms扫描的离线替身在两笔各延迟3秒成功响应的条件下，MainReady 后需11400ms才得到 STOP/OFF 和 CommReady；HMI 现阶段预算为10400ms。起点偏移、状态发布与读数阻塞会影响实际表现，不能声称所有现场精确10.4秒失败；但现有期限尚无双方一致的覆盖证明，70.4秒总预算不能替代局部期限。反例不是 Siemens 内部重试仿真、TIA 编译或现场测量。

恢复/人工锁解除契约仍待两端明确；配套 PLC 的 TIA SCL 导入/编译尚需核验，候选未经验收不得下载。完整计时边界见 [PLC 对接清单第 10 节](PLC_CONTRACT_CHECKLIST.md#10-114-秒反例与-hmi-阶段预算的边界)。本轮不调整 PLC 期限、反馈有效期或解锁指令。
