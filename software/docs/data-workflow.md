# 测试数据与审批

本手册说明 `reliability_v1` 中一份测试记录从工位保存、核实上传到审批发布的操作流程。

## 以一次手臂测试为例

假设测试员已完成一次手臂测试，运行时开启了采集记录，并选择了平台中已有的样品、计划和正式用例。接下来按以下顺序保存和提交结果。

### 1. 找到本机记录

测试结束后，上位机整理原始 CSV、汇总和报告。通过安装包或 `host/launch.py` 启动、使用默认状态目录时，文件保存在：

```text
~/.local/state/rp1-test-hmi/data/executions/<测试编号>/
├── telemetry/raw.csv        原始采集副本
├── analysis/summary.json    自动分析汇总
├── analysis/report.md       本机报告
└── operator_review.json     确认提交时保存的人工核实记录
```

使用 `--state-dir` 或 `XDG_STATE_HOME` 时，先用同一配置运行 `rp1-test-hmi status` 查看 `state_root`，再进入其下的 `data/executions/`。记录结束时文件仍保存在工位，上传由后续的“确认提交”发起。

### 2. 核实并确认提交

在上位机的“老化测试”页登录测试平台，在“运行记录与关键结果”中选择本次记录，点击“提交审批”。在“核实并提交”窗口中核对自动分析，填写实际测试人、工位、人工结论和测试员备注；人工结论与自动结论不同时补充差异原因。确认后点击“确认提交”。

上位机保存核实记录，将本次请求和原文件校验信息加入本地上传队列。上传中断后，可选择同一记录点击“重试归档”续传。

### 3. 在网页查看归档和曲线

用提交账号登录网页，打开“数据归档”，按执行编号查找本次记录。文件校验、解析完成后，点击“详细曲线”查看采集数据，并核对自动分析和人工核实内容。

服务器把原件和派生查询文件保存在中央归档持久卷，容器内路径为 `/var/lib/rp1/archives/<执行UUID>/`；宿主存储位置按站点的 `RP1_ARCHIVE_VOLUME` 配置确定。工位继续保留本地副本，日常查询通过网页进行。

若记录显示“未送审”，先在归档页核对正式用例和样品归属，缺项时补齐，再由原提交人填写提交说明、点击“送审”。显示“待审核”时，进入下一步。

### 4. 审核并查看正式结果

执行员或管理员进入“测试数据审批”，打开该记录，核对原始归档、自动分析和人工核实，填写审核意见，选择“批准并发布正式记录”或“驳回”。现有权限允许审核本人提交的记录。

批准后，点击“查看正式执行”查看发布结果，申报时长进入正式台账。驳回时，原提交人按意见追加核实或归属修正版本，再重新送审。

## 数据使用规则

- 账号权限决定谁能操作；测试数据审批决定哪一版记录可以发布。上传回执表示文件接收进度，正式发布以 `APPROVED` 为准。
- 原始测量数据保持只读。人工核实、归属修正和重新分析分别追加版本，保留原值、文件哈希和处理记录。
- 待归类、待审核和驳回记录供有权限的提交人、管理员等核对；正式查询和统计使用已批准、已归类的记录。
- 时长台账与 MTBF 分别计算。批准后的申报时长进入台账；计入 MTBF 的有效运行时间还需经过资格、统计范围和同一样品区间去重检查，详见[数据库规则](../database/README.md)。

## 本地记录与身份

每次记录用原件大小和 SHA256 标识采集文件，用执行 UUID 标识本次测试。归档编号、正式执行编号和纠正前编号通过身份及别名关联。

开始记录时有两种选择：

- **正式用例**：选择平台已有的样品和测试计划。平台档案同时关联本次周期、配置、分析段、用例版本和工位；缺项时补齐后再使用该档案。
- **其他**：填写测试名称、实际对象和工位，先保存本地记录，核实上传后可查看归档和曲线，再补正式用例归属。

本地独立记录使用本机工位信息。接口对接时，分别核对平台工位标识 `station_id` 和工位/台架关联字段 `bench_id` 的定义与取值。

## 归档与送审

```text
工位结束并保存原件 → 用户核实 → 显式提交 → 专用接口分块上传
    → Worker 校验 SHA256 并解析 → 查看归档和曲线
    → 补齐正式归类及执行上下文 → 送审 PENDING
    → APPROVED / REJECTED
```

上传队列使用本地 SQLite 保存已确认的核实内容、原件大小、哈希和提交账号。重试沿用这份记录；如果文件发生变化，上传会被拒绝，需先核对原始文件。

“其他”上传后处于 `UNCLASSIFIED`（待归类）。在归档页选择已有计划中的正式用例和样品，保存正式归属后再送审。每次送审关联具体的核实、归属版本。

PostgreSQL 保存身份、文件索引、核实/归属版本及审批记录；API 和归档 Worker 共享仓库之外的文件持久目录。前端通过 API 按权限查询。

## 权限与正式发布

| 操作 | 权限与约束 |
|---|---|
| 提交 | 用执行员或管理员账号登录；服务端记录当前提交账号并校验本次测试的计划、样品等关联信息 |
| 核实、归类、送审 | 除角色外，按原提交人、管理员职责和具体接口权限检查 |
| 审核 | 执行员、管理员可审核，包括本人提交，必须填写意见 |
| 查看者 | 不能提交或审核；归档须已批准并完成正式归类，业务读取仍执行权限检查 |
| 建档 | 样品、项目、计划和台架创建受管理员权限限制；关联操作另查资源权限 |

网页登录与 HMI 平台登录使用个人账号会话，写请求携带 CSRF 校验信息。应用权限和 PostgreSQL 行级权限（RLS）共同检查资源访问范围。

提交、不可改写的提交版本和审核记录分别保存；审核关联版本、审核人、结论、理由和时间。已批准版本不能覆盖或撤回；驳回后修正并显式重提，追加版本，保留旧证据和意见。

批准在同一数据库事务中检查当前版本、原件校验、冻结核实、归类、权限及上下文，发布执行、结果、运行时段、身份关联与审核记录。外键、区间重叠或版本错误会回滚整次发布、审计和重算任务。

发布结果分别保留机器测量、自动分析和人工结论，供查询时对照。

## 幂等、并发与恢复

- 提交和审核携带稳定幂等键、版本号。同键同内容重放原结果，同键改内容或版本冲突返回 409。
- 锁与唯一约束保证同一次执行只发布一次；并发审核或执行身份冲突返回冲突信息。
- 网络中断保留本地文件和队列，按已确认分块续传。回执丢失沿用冻结正文/幂等键，不重复创建。
- 队列绑定原提交账号，切换账号不消费他人队列。待审只查状态，驳回停止自动重试，修正后显式重提。
- API/Worker 重启从持久状态恢复；校验或解析失败时保留失败状态和错误信息，按错误处理后重试。
- 重新分析引用已发布用例的可计算规则，追加操作者、规则版本、原件哈希与结果；无可计算判据时为 `UNCONFIGURED`，不覆盖原分析、人工意见或正式结果。

## 网页历史 CSV 导入

在“数据归档”点击“数据补录”（地址参数为 `?view=csv-import`），选择文件并预览，填写测试信息、核实后上传。后续使用同一套归档、解析和审批流程；遇到重复文件提示时，先查找已有归档。

原文件没有采集日期时，原始采集时间保持未知；人工补录的起止时间单独标记。曲线来自原始采样文件，统计资格按实际数据质量和来源审核。文件名和文件修改时间不作为采集日期依据。

## 在线监控与正式统计

HMI 登录后，网关默认每 10 秒发送工位、账号、并行会话、运行/暂停/故障及 PLC 状态，单次请求最长等待 5 秒。心跳独立于 CSV 上传队列。断网不积压旧心跳，恢复发送当前快照，序号阻止旧状态覆盖新状态。

网页分别显示在线状态、历史快照和待确认状态。设备停机应在现场核对实际反馈；离线或电柜供电状态本身不反映测试是否运行。监控仅展示状态，PLC 和电机控制在工位进行。

在线记录可关联本次执行身份；结束后按本手册完成核实、归档和审批。MTBF 的待确认时间与故障单独显示，历史申报时长经受控确认后按数据库约束评定资格。

当前平台统一使用专用归档接口接收采集 CSV。旧 `/api/v1/ingestion` 已停用；通用附件和执行包不作为测试数据发布入口。

| `frontend/src/pages/ArchivesPage.tsx`、`frontend/src/pages/SubmissionsPage.tsx`、`frontend/src/pages/CsvImportPage.tsx`、`frontend/src/pages/CurveAnalysisPage.tsx` | 归档、审批、补录与曲线 |
