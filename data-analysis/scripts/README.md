# 离线分析软件

将采集文件转为可核对的指标、事件时间线和基线对比。**当前只有说明，三个脚本尚未实现；暂不提供运行命令。** 首版计划采用Python并保持少量依赖，读取导出文件即可分析。

## 计划入口

| 脚本 | 输入 | 计划输出 |
|---|---|---|
| `analyze_run.py` | 遥测、事件、运行元数据与分析配置 | `summary.json`、`report.md`：关节温度、误差、有效时长及数据缺口 |
| `compare_runs.py` | 基线/试后记录或摘要、双方配置 | 指标对比表：可比工况、变化与不一致项 |
| `summarize_events.py` | 事件、任务区间与故障标记 | 暂停、保护、人工干预及故障时间线 |

输入沿用现有 `rp1_test` 落盘格式，并通过 [config](../config/README.md) 映射字段和单位。采集与执行软件分别位于 [上位机](../../software/host/README.md) 和 [test-runner](../../software/test-runner/README.md)；本目录处理运行后的数据。

## 统计规则

- 有效任务时长取已确认 active intervals 的持续时间；不从采样点数或运行首尾时间猜测。采集缺口与任务区间分开报告。
- 跟随误差以反馈位置减指令位置计算，统计同工况的 active 样本；输出绝对峰值、均方根和有效样本数。角度环绕按明确配置处理。
- 温度峰值覆盖全程，包括计划暂停、异常停机与后续冷却；缺少环境温度时不输出温升。
- 缺失读数保持未知，不填0；重复或倒序时间需标记并按记录规则处理。
- 阈值只产生观察标记，缺少阈值时描述实测值。单次运行不推 MTBF，也不自动产生正式 PASS。

## 按用例使用

站立/行走先运行单次分析，核对时长、温度和误差；热保护先汇总事件，确认告警、降额、停机顺序；改进复测再比较相同动作、负载及环境下的基线。工况不一致时先解释差异，不能直接把变化归因于改进。

输出需记录输入来源、统计范围和工具版本，并说明缺失、暂停、重复时间与单位转换的处理。
